# Tareas y estado del proyecto

## Convenciones
- [ ] Pendiente
- [x] Completado
- No marcar una tarea como completada solo porque el código parezca correcto; anotar la prueba realizada.

## Estado inicial
- [x] Crear repositorio de GitHub.
- [x] Añadir el HTML actual al repositorio.
- [x] Documentar las reglas comunes de trabajo.
- [x] Registrar la arquitectura conocida y sus límites.
- [ ] Abrir el HTML en el navegador y confirmar que carga correctamente desde una copia local.
- [ ] Probar exportación de copia de seguridad y volver a importar esa copia.
- [ ] Comprobar que los datos se conservan al cerrar y volver a abrir el navegador.
- [ ] Crear una lista breve de flujos críticos para probar antes de cada cambio.
- [ ] Decidir si conviene trabajar con ramas para cambios que afecten a cálculos o datos.

## Reglas para nuevas tareas
Antes de empezar una tarea, escribir:
1. Resultado esperado.
2. Qué partes pueden modificarse.
3. Qué partes deben permanecer intactas.
4. Cómo se comprobará que funciona.

Después de terminar, registrar:
- Archivos modificados.
- Pruebas realizadas.
- Resultado.
- Problemas o dudas pendientes.
